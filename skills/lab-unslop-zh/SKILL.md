# unslop-zh：中文成稿的最后一道工序

## 什么时候用

成稿是中文就用，三种情形同一套做法：直接写中文、改已有的中文、把英文材料写成中文。

成稿不是中文就**不用**，改用 `unslop`。把中文译成英文也不用。

## 一条核心

**以中文为第一语言写出来，不要逐句翻译。**读完整段，弄懂意思，然后像中文作者那样写：
该断就断，该换顺序就换顺序。逐句对译是失败的做法，不是方法。

## 优先次序

有冲突就由上往下让步：

1. **事实与确定性。**不添原文没有的数字和细节，不把「可能」改成「确定」，「研究表明」
   一类的出处保留。
2. **用户划定的范围。**没让你改的地方不要改。
3. **作者的语气和称呼。**见下。
4. **文风。**

拿不准的改动，撤回。

## 三页 reference

| 页 | 什么时候读 |

| `references/ouhua-diagnosis.md` | 句子别扭，要找出是哪一类词在坏事 |
| `references/ouhua-repair.md` | 要改写，或要判断某处西化该不该留 |
| `references/ouhua-self-check.md` | 写完自检，怀疑自己是在译而不是在写 |

判断一处西化该留该改，问一句：**它比对应的中文说法多带来了什么？**说不出来就改掉。

## 不构成修改理由

被动句、名词化、长句、首先/其次、句内排比、代词少、重复用全称、疑问句、比喻。

这些区分不出机器写的中文和人写的中文，动手就是瞎改。**这个 skill 最容易败在改得太多，
不是改得太少。**好的长句是好中文，不要拆。

## 排版、人称、术语

**定死的**：中英文之间半角空格；中文标点用全角；数字用半角；品牌和产品名按官方大小写。

**跟随文件既有写法的**：数字和单位之间空不空格；引号用「」还是""。文件里没有先例才用默认
（数字和单位之间空一格，引号用""）。同一文件里不混用两种引号。

**人称**：优先不用人称（「可使用」而不是「你可以使用」）。非用不可就跟随文件既有的写法。
**不要把「您」改成「你」，也不要反过来**，除非用户要求。

**术语**：有通行译名的，首次写成「中文（English）」，之后只用中文。标识符、命令、文件名、
格式、仪器型号、产品名保留原文。目标仓库里的 `AGENTS.md`、`CLAUDE.md` 或术语表优先于这里。

## 和 unslop 的关系

中文成稿只跑这个 skill，不叠加 `unslop`。`unslop` 里不分语言的规则照样成立，按编号引用：
第 7（AI 词汇）、9（不是 X 而是 Y）、10（三段式）、23（废话）、27（说清楚做什么，而不是
什么感觉）条。

三条在中文里改写：

- 第 13 条（禁破折号）→ 中文的「——」是正常标点，但 AI 用得过多。该用句号或逗号的地方别用。
- 第 17 条（标题句首大写）→ 中文无此概念，不必管。
- 第 19 条（直引号）→ 中文用全角引号，见上。

`bro` 的标准照旧：说人话，不堆术语。
